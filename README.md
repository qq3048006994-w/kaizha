# 《开铡》

**一纸诉状，四堂审判。**
**不问贵贱，只问是非。**

中国古风互动审案游戏。玩家扮演北宋开封府尹包拯，在四轮审案中收集证物、推演证据关联、质询证人与被告，最终在王法与皇权之间作出抉择，决定陈世美一案的四种结局。

> 本作依据民间故事与戏曲题材作游戏化改编，人物、地名与情节为叙事需要作了调整，**不作为史实陈述**。

---

## 一、快速开始

```bash
npm install     # 安装依赖
npm run dev     # 本地开发预览 http://127.0.0.1:5173
npm run build   # 产出离线可用的 dist/ 目录
npm run preview # 预览生产构建
```

已有 `package-lock.json` 时，建议用 `npm ci` 安装锁定版本。本次云端验收使用 Node.js 24.22.1、npm 11.9.0 和系统 Chromium。

游戏不依赖任何外部服务器、在线 API 或在线图片素材，安装完成后可完全离线运行。

第一次游玩：各堂开场的「本堂要点」会说明操作目标。选项是查问方法，证物需实际调查取得；第二堂将两至三件证物关联，第三堂以证据质询，第四堂再作裁决。失败关联不会扣除证物，可利用原有「回到上一步」重新查问。终审和结局的「判词依据 · 证据回顾」解释当前缺项，不会替玩家选择判决。

现场展示可参考 [3—5分钟演示路线](docs/DEMO.md)。该时间为讲解预算，不是虚构的真人平均通关时长。

## 三、玩法与系统

### 四堂审案

| 轮次 | 名称 | 核心目标 |
|---|---|---|
| 片头影像 | 序 | 74 秒开篇背景故事影像，全屏播放，播完自动进入第一堂；右上角「跳过片头／直接断案」随时可跳过 |
| 第一堂 | 鸣冤·初审 | 接收状纸，确认秦香莲与陈世美的婚配、亲子关系与拒认经过 |
| 第二堂 | 验刀·追凶 | 查明韩琪身份、钢刀来处、三官堂验状，并完成三组**证据关联推演** |
| 第三堂 | 对质·辨伪 | 多轮质询陈世美，用证据揭穿他的辩解；面对公主府施压 |
| 第四堂 | 御压·终审 | 太后懿旨与公主请求当堂到来，最终判决由玩家落笔 |

### 证据关联

第二堂可打开「证据关联推演」案台：选取两至三件已取得的证物进行推演。

- 关联成功：给出该证据链的推理反馈，并记入卷宗（卷宗右上角进度即时更新）。
- 关联失败：不显示标准答案，只给出方向性提示。
- 三条证据链：**婚配与亲子**、**凶器与差遣**、**忠义两难**。

### 四种结局（由游戏状态计算，非随机）

| 结局 | 触发条件 |
|---|---|
| 正法昭彰 | 七件核心证物齐备、三条证据链成立、第三堂关键印证成功，且终审选择依法审判 |
| 抗旨开铡 | 上述条件齐备，且终审选择当面抗旨开铡 |
| 权门蔽日 | 终审选择遵从懿旨、移交宗正府 |
| 悬案待雪 | 证据不足或关键印证未完成仍坚持继续查证，或终审选择暂缓宣判 |

结局达成后自动写入「结局档案」，首页可查看已解锁的四种结局。

### 界面与档案

- 首页：电影海报式构图，使用授权书法标题图。
- 审案页：堂审进度、人物立绘、逐字对话、质询选项、惊堂木音效。
- 证物系统：8 件证物的来源、调查状态、查验要点、关键印章与关联状态。
- 人物志：五位角色的立绘档案，按审案进度解锁（韩琪、公主分堂解封）。
- 案件卷宗：已知事实、关键证物进度、证据链进度、明察与威压数值。
- 审案记录：逐条留存的对话、抉择与堂上回响。
- 设置：背景音乐、音效、文字速度、自动播放、跳过已读、文字大小、手动存档、返回主菜单、重置游戏。

### 审案对话舞台（单人近景 · 谁说话谁出现）

审案页采用视觉小说式的「单人近景立绘」：角色半身、居中、完全不透明，可实地遮挡公堂背景，
下缘由对话框自然裁出半身；不再出现两人一左一右贴边、中间空堂或半透明「幽灵」。

- **谁说话谁出现**：舞台只解析当前 `node.speaker` 一位角色，任何时刻最多一人；
  旁白、太后、公孙策、展昭等无立绘角色说话时舞台留空，公堂背景干净。
  玩家视角的包拯说话时同样登场（有 `bao-bust.png`）。
- **素材**：`public/assets/characters/stage/*-bust.png`，由 `scripts/build_stage_busts.py`
  从人物志白底半身照（641×790）抠出透明底，裁掉顶部留白后统一 641×730；
  五人头顶位置、比例、水平中心一致，切换角色构图不跳动。
  四角透明、中心不透明、底边 5% 短渐隐由 `npm run test:stage` 逐张校验。
- **抠图白边清理**：`scripts/build_stage_busts.py` 采用「确定背景 + 按到背景距离
  分层剥离浅色过渡带」。头发/发髻/鬓角残留的白色其实不是纯白块，而是紧贴轮廓的
  灰白抗锯齿带（mn≈204~244），旧版严格阈值会把它们从背景连通域里切断而留下白边；
  现按「离背景越近、越白越判为背景」逐层剥离，并用「邻域必须含深色」门控区分
  「背景白↔深色头发」与「背景白↔浅色白袍」，避免把陈世美白袍外沿啃出缺口。
  白袍内部被误判成连通背景的纯白高光，用「人物实体核心」精确回填；透明区 RGB
  用最近前景色填充，消除浏览器缩放时的白色渗边。阈值依据见 `scripts/probe_white_levels.py`。
  **包拯脸颊/耳下两缕「显白」**经原白底图同区域放大对照确认是**人物自带的银灰鬓髯**
  （细丝纹理、与黑髯自然衔接，原图呈浅灰而非纯白），不是抠图残留；直接删 alpha 会在
  脸颊挖出两个透明洞、露出公堂背景，反而毁造型，故只对该区域做 **RGB-only 压暗**
  （中性浅灰线性映射成深灰褐，保留发丝明暗与轮廓），alpha 与人物完整性完全不动。
  像素级验收 `npm run check:bust-white`：白边残留、白袍零破洞、鬓髯区显白占比 ≤6%、
  641×730、四角透明，并输出 `test-artifacts/bust-*-check.png` 深绿底放大对照图。
- **取图链**（`src/assets.js` 的 `stagePortraitSources`）：
  `character.stageBust` → `stageBusts[id]` → 本人侧身立绘 → 本人通用透明立绘；
  只取本人图，绝不串角色、绝不水平镜像。给无立绘角色补任一路径即自动登场，无需改组件。
- **站位**：立绘恒居中（`.stage-focus` 的 `left:50% + translateX(-50%)`），
  随视口只做等比缩放（1920/1600/1366/1280/900/390 已验收），大致位置不变；
  `characters.defaultSide` / `node.side` 现在只决定名牌贴左还是贴右。
- **不遮挡 UI**：舞台 `z-index:3`，对话框 10、证据链面板 5、顶栏 20 均在其上；
  舞台 `pointer-events:none` 不拦截点击。人物不做任何整体淡化 / 降饱和度。
- **组件**：`CharacterPortrait`（取图与回落）、`DialogueStage`（单说话者解析）、
  `SpeakerPanel`（姓名 + 身份）。`court.cast` / `node.cast` 为旧双人站位数据，保留但不再读取。

### 反悔机制（回到上一步）

玩家可随时撤回自己的操作，重新抉择：

- **案件卷宗 → 审案记录面板**：顶部「回到上一步」按钮；每条记录右侧另有「回到此处」，可跳回该次抉择之前的状态。
- **审案页底栏**：「回到上一步」按钮，跨堂回退同样有效。
- **结局页**：「反悔 · 回到终审前」，撤销已落笔的判决，重新选择结局。
- 每次抉择或证据推演前自动压入一次快照（最多保留 30 步）；快照只记录状态字段与历史长度，不复制整份对话记录，存档体积不会膨胀。
- 覆盖已有存档时弹出**游戏内自绘**确认框（不使用原生 `window.confirm`，避免在 Electron / 部分浏览器中被拦截），确认后才另立新卷宗。

```
│  ├─ portraits/        # 角色头像
│  ├─ logo/             # 透明化书法标题
│  ├─ video/            # 开篇背景故事影像 intro.mp4（H.264 / 1280×720 / 74 秒）
│  ├─ evidence/          # 证物素材目录（证物图形为 src/components/EvidenceIcon.jsx 内联 SVG）
│  └─ fonts/            # 授权字体接入位（见说明文件）
├─ scripts/             # 素材处理脚本、端到端验收脚本、桌面启动脚本
├─ src/
│  ├─ components/       # 对话逐字机、案卷弹窗、证物图标、关联案台
│  ├─ pages/            # 首页、审案页、结局页
│  ├─ data/             # 人物 / 证物 / 剧情（数据化）
│  ├─ game/             # 结局判定与存档系统
│  ├─ hooks/            # 音频（Web Audio 合成，无外部音频文件）
│  └─ index.css         # 视觉体系（色彩变量、排版、动效、响应式）
└─ test-artifacts/      # 验收截图与结果
```

```bash
npm run lint      # ESLint（React Hooks 规则）

npm run test:undo  # 反悔机制专项验收（21 项）
npm run test:chapter-font # 章节页字体规范与「升堂」按钮验收（55 项）
npm run test:stage   # 单人近景舞台专项验收（107 项 + 6 视口 / 5 角色截图）
npm run check:dist   # dist 离线校验（自带静态服务器，KAIZHA_DIST 可指向新构建目录）
npm run check:nameplate    # 人物名牌文字框内居中校验
npm run check:no-bold      # 金色浮雕标题不加粗校验
npm run check:archive-white # 人物档案白底大图规格校验
npm run check:bust-white    # 近景立绘抠图验收（白边残留 / 白袍破洞 / 尺寸 / 透明）
npm run check:fonts # 全站字体族/字号/加载状态核对
npm run test:endings-flow # 从新游戏自然通关四结局、两种失败条件及手机完整流程
npm run test:reliability # 异常续档、备用档、回退定位、新开局、全文展开、菜单暂停和重置
npm run test:review # 构建、lint、全部单元测试及上述已有/新增浏览器与立绘验收
npm run test:round2 # 第二轮引导、反馈、判词复核和异常存储场景（隔离测试数据）
```

`test:review` 为已有 Windows 路径测试提供独立的平台适配，不修改游戏数据或测试断言。Linux 默认使用 `/usr/bin/chromium`；可用 `KAIZHA_BROWSER` 指定浏览器可执行文件，未指定且没有系统 Chromium 时使用 Playwright 管理的 Chromium（需预先安装）。Python 立绘检查需要 Pillow、NumPy 和 SciPy，可用 `KAIZHA_PYTHON` 指定解释器。请勿同时运行占用相同端口的测试。

新增自然流程测试使用独立浏览器上下文，所有证物和证据链均由界面操作获得，七条路径分别覆盖依法、抗旨、移交、暂缓、缺证、质询失败及 390×844 手机通关。可靠性测试仅在独立上下文内构造边界存档，不使用或清除演示浏览器的档案。完整矩阵日志写入 `test-artifacts/review/<运行时间>/`，失败会返回非零退出码。既有 `test:endings` 仍是注入终局的页面显示检查，不能代替自然通关测试。

第二轮场景结果写入 `test-artifacts/round2/experience.json` 与 `storage-feedback.json`。自动存档状态以实际写入结果为准；失败时当前会话仍可继续，但刷新可能丢进度。结局入档失败会保留结局页面并提示，重置删除失败不会假报成功。异常卷宗不会自动清除；损坏结局档案可显示其中安全的记录并给出警告，原文保留以备检查，不直接覆盖。

### 技术结构与验证边界

| 层次 | 入口/文件 | 职责 |
| --- | --- | --- |
| 应用与状态 | `src/main.jsx`、`App.jsx` | 页面切换、单一案件状态、抉择/回退、持久化结果反馈 |
| 内容数据 | `src/data/story.js`、`evidence.js`、`characters.js` | 四堂剧情、证物关联和人物；第二轮未改核心内容 |
| 判定 | `src/game/endings.js` | 七件关键证物、三条证据链及三项质询共同决定依法/抗旨结果 |
| 只读复核 | `src/game/caseReview.js` | 复用判定规则解释证物/关联/质询缺项，不改游戏状态或增加评分 |
| 持久化 | `src/game/save.js`、`settings.js` | 版本1卷宗校验、安全档案恢复、设置枚举规范化 |
| 呈现与验证 | `pages`、`components`、`scripts/review-*.mjs` | 保留古风界面；浏览器矩阵与隔离场景验证 |

仓库没有自动AI评委评分脚本。审查文档中的分数属于主观模拟，不是赛事得分；没有真实人类/AI投票比例时，不能计算 `7×人类投票比例 + 3×AI投票比例` 的官方单项成绩。

`test:e2e` 会真实启动开发服务器，用 Chromium 跑通：首页三个档案面板 → 开始审案 → 第一堂质询 → 手动存档 → 刷新续档 → 第二堂错误关联提示与三组成功关联 → 第三堂证据质询 → 第四堂皇权压力 → 终审二次确认 → 正法昭彰结局，并在 1920×1080 / 1600×900 / 1366×768 / 1280×720 / 390×844 五种视口检查横向溢出与元素错位。截图输出在 `test-artifacts/`。

> 端到端脚本使用系统已安装的 Edge（`C:/Program Files (x86)/Microsoft/Edge/Application/msedge.exe`）。若在其他机器运行，请修改 `scripts/e2e.mjs` 中的 `executablePath`，或先执行 `npx playwright install chromium`。

## 六、桌面安装包（Windows）

桌面版代码与打包配置已就绪，但**当前仓库未预装 electron / electron-builder**（体积较大），请按以下步骤生成安装程序：

```bash
npm install --save-dev electron electron-builder
npm run desktop:dist      # 产出 release/开铡-Setup-1.0.0.exe
```

- `npm run desktop:pack` 仅生成免安装目录，便于快速验证。
- 安装包提供桌面与开始菜单快捷方式，双击即可运行，不需要命令行、浏览器或联网。
- 游戏数据保存在系统用户目录的 localStorage 中，卸载应用不会删除用户存档。
- 若需在开发模式下调试：`npm run desktop:dev`（自动拉起 vite 并打开 Electron）。

## 七、字体与授权说明

全站采用以下三款主用开源字体，并保留志莽行书作为章节行草字体的回落；字体文件随包离线分发：

| 字体族 | 文件 | 用途 | 气质 |
| --- | --- | --- | --- |
| 龙藏体 | `LongCang-Regular.ttf`（OFL-1.1） | **每堂章节主标题**「鸣冤」「合证」「折辩」「开铡」 | 狂草枯笔、象牙白飞白，笔势狂放连绵 |
| 霞鹜臻楷 Level1 | `LXGWZhenKai-HanOnly-Level1.ttf` | 人物姓名、按钮主文案、卷宗标题等醒目位置 | 圆润粗楷，标题金色渐变 + 描边 + 多层投影浮雕 |
| 朱雀仿宋 | `ZhuqueFangsong-Regular.ttf` | 对话、正文、卷宗、证物说明、按钮副文案 | 方正瘦宋，长段落阅读不疲劳 |

- 字体族通过 CSS 变量统一调度：`--font-title`（标题族）、`--font-kai`（楷体族）、`--font-body`（正文体），主副标题不同族，形成「圆粗标题 + 瘦宋正文」的对比。
- 主标题（章节页 116px、结局页 76px）采用金色渐变 `background-clip:text` + `-webkit-text-stroke` 描边 + 三层 `text-shadow` 浮雕；副标题取主标题约 **1/3**（章节页 33px，比例 0.28），用朱雀仿宋浅灰暗白，与主标题不同族不同色。
- 字体文件随 `dist` 一并打包（`dist/assets/fonts/`），网页版与桌面版均可完全离线使用，无需本机安装。
- **已知限制**：霞鹜臻楷 Level1 为「汉字-only」子集，缺 27 个字符（如《》。、懿、驸、刎、测等）。浏览器按字体栈自动回退到朱雀仿宋（覆盖 0 缺字），不会出现豆腐块。龙藏体与志莽行书均仅缺 1 字（「開」），章节标题用字全部命中。
- **未采用的文件**：`LXGWBoldKai-HanOnly-Level2A.ttf` 经 sfnt 表解析确认缺少 `glyf`/`cmap` 表（仅有 BASE/FFTM/GDEF/GPOS），任何环境都无法渲染（canvas 像素签名与 sans-serif 完全一致，PIL 渲染为全方框），因此未纳入工程、已移除。标题的「粗」由 `font-synthesis: weight` 合成加粗 + 描边浮雕实现，视觉接近粗楷。
- 若日后需要更换为商业字体（如方正宋刻本秀楷 / 方正清刻本悦宋），步骤见 `public/assets/fonts/字体接入说明.txt`：放入授权文件 → 启用 `@font-face` → 修改 `--font-*` 字体栈 → 重新 `npm run build`。

字体专项验收脚本：`node scripts/check-fonts.mjs`（加载状态、主副标题族与比例）、`node scripts/measure-fonts.mjs`（canvas 像素签名，确认两款字体真实生效且互不相同）、`node scripts/e2e-chapter-font.mjs`（章节页 55 项：字体族/字号/按钮色值/无重叠截断/五档视口）。

### 章节页字体规范

每一堂的章节页统一遵循同一套字体分工：

| 位置 | 字体族 | 说明 |
|---|---|---|
| 章节主标题「鸣冤」等 | **龙藏体**（狂草族 `--font-brush`） | 122px，象牙白枯墨渐变 + 淡白描边 + 浓墨重描投影；逐字独立成 span，首字左倾 4° 微上、末字右倾 3° 微沉，模拟狂草连笔走势；字距 .1em 保证**两字包围盒不重叠** |
| 副标题「一纸状词，先问名分」 | 方正清刻本悦宋 → 朱雀仿宋 → 霞鹜臻楷 | 33px，浅灰暗白 |
| 正文、按钮、章节编号等 UI | 同上两款（方正优先） | 章节编号用秀楷位 |
| 底部「升堂」主操作按钮 | 方正清刻本悦宋（悦宋位） | 23px / 700，暖象牙白 `#F4E8D0` + 暗朱红 `#983D2D`，无阴影/无浮雕/无发光，轻微字间距，尺寸位置与交互逻辑不变 |

**标题一律不加粗**：所有金色浮雕大标题（章节页、结局页标题、确认框标题、证据关联台标题、卷宗各级标题）统一 `font-weight: 400` + `font-synthesis: none`，避免浏览器把仅有 400 字重的字体合成为伪粗体；视觉重量改由描边（1.6px）与投影承担，走细笔挺拔一路。

**人物名牌框内居中**：对话区左上的人物名牌（「旁白 / 公堂叙事」「包拯 / 开封府尹」等）文字在框内水平居中。因 `letter-spacing` 会在每个字右侧留空隙（含末字），仅设 `text-align: center` 会使文字整体偏左；故按**半个字距**补偿 `text-indent`（主文字 `.125em`、副标题 `.06em`），实测主文字中心与框中心偏差 1.31px、副标题 0.33px。

方正两款字体目前**未获得授权文件**，工程内以 `local()` 方式声明：玩家本机若已安装则直接调用，未安装时自动回落到已打包的开源同风格字体（霞鹜臻楷≈秀楷位、朱雀仿宋≈悦宋位），不会出现豆腐块、不阻塞渲染。授权文件到位后按 `public/assets/fonts/字体接入说明.txt` 放入并重新构建即可自动启用。

## 八、素材说明

- 人物立绘由用户提供的角色设定图提取全身像并做背景分离，白边与残留背景已清理，比例与服装（含陈世美白色锦袍、鞋履）保持原样。
- **人物档案大全身照使用原始白底设定图**（取自用户首次提供的角色设定集，未抠图）：包拯、秦香莲、韩琪、岚萍公主从各自设定集的人物列自动裁剪，陈世美直接使用独立白底全身图。档案图容器底色同步改为纯白 `#ffffff`，竖排姓名与身份印章配色适配白底。左侧角色列表缩略图保持抠图小头像不变；公堂审案立绘仍用透明底图（便于叠加公堂背景）。
- **五张白底大图规格统一**：档案大图容器宽度固定、图片按宽度撑开，若各图宽高比不一致，显示效果会差很多（窄图被放成大脸、宽图缩成全身）。因此由 `scripts/normalize_white_fullbody.py` 统一输出为 **641×790 纯白画布**：人物等比缩放使「头顶→脚底」高度与包拯一致（1488px）、头顶留白 77px、水平居中；设定集里的文字笔画用开运算刷白，陈世美的透明网格底与 AI 水印一并净化；画布高度直接取裁切线 y=790，**手部（约 y=800–950）刚好全部不可见**。这样包拯、秦香莲、陈世美三者的构图、大小、居中位置基本一致。
- **不留下方空白**：旧版把画布补到 1600 高、人物只占前 790 行，其余 810 行纯白；图片固有宽高比会把整个档案面板撑到约 1093px 高，页面出现大片空白。现改为按裁切线直接出图，并在 `src/index.css` 把大图设为 `object-fit: cover; object-position: center top`（档案面板两列改为 `1fr 1fr`，让桌面端容器宽高比与图片一致、零裁切），任意视口下图片都铺满白底容器、不产生 letterbox，人物从「头顶」到「手刚好看不见」刚好填满面板。
- 验收：`npm run check:archive-white` 会预置第三堂存档解锁全部五人，断言五张图均为 641×790、底部纯白尾 ≤10px、头部中心偏差 ≤40px、容器纯白、大图 `object-fit: cover` 且顶部对齐、固有尺寸为 641×790（不是旧版 1600 高）、面板高宽比 ≤1.8（旧版为 2.496）、图片与容器等高；并在 1920×1080 / 1600×900 / 1366×768 / 1280×800 / 900×800 / 390×844 六档视口用 canvas 模拟 cover 取底部 18% 像素，确认不是纯白空白；五个人物逐个点开截图，左侧栏仍是缩略图。
- `public/assets/source/` 保留了全部原始素材，未覆盖、未二次压缩。
- 书法标题由参考图去除白底生成透明底图，保留原笔势与飞白质感，未替换成普通字体标题。
- 公堂背景、惊堂木场景与书房场景均来自用户提供的素材。

## 九、片头影像说明

- 文件：`public/assets/video/intro.mp4`（1280×720，74 秒，约 24 MB），随构建一起打包，离线可播。这是**开篇后讲解背景故事**的影像：首页点「开始审案」后全屏播放，播完自动进入第一堂章节页。
- 当前片源已是 **H.264 (avc1) + AAC-LC + yuv420p**，浏览器与 Electron 可直接解码；已用 `ffmpeg-static` 做**无损重封装**加 `+faststart`（moov 前置，可边下边播、可拖动进度），没有重编码，画质无损。
- **历史坑**：更早的一版片头是 HEVC / hvc1，Chrome/Edge 未装「HEVC 视频扩展」时只能解出音轨、画面全黑（`videoWidth=0`），故片头一律统一成 H.264。
- 替换片头：先删除旧的 `intro.mp4`，再把新片放进 `public/assets/video/` 覆盖同名文件。若新片已是 H.264 + AAC，只需无损重封装；若仍是 HEVC 或编码不兼容，才需要重编码：

  ```bash
  node -e "console.log(require('ffmpeg-static'))"   # 取 ffmpeg 路径
  # ① 已是 H.264 + AAC：无损重封装，前置 moov（推荐）
  node_modules\ffmpeg-static\ffmpeg.exe -y -i 新片.mp4 -c copy -movflags +faststart public\assets\video\intro.mp4
  # ② HEVC / 其它编码：重编码为 H.264
  node_modules\ffmpeg-static\ffmpeg.exe -y -i 新片.mp4 -c:v libx264 -preset slow -crf 22 \
    -pix_fmt yuv420p -c:a aac -b:a 128k -movflags +faststart public\assets\video\intro.mp4
  ```
- 改完记得同步 `dist/assets/video/intro.mp4`（或重新构建），并跑 `npm run test:e2e` / `npm run check:dist` 验证「可解码播放 / 播完自动进入章节页 / 可跳过」。
- 片头只在「开始审案」时播放一次；「继续案件」直接回到公堂，不会重复播放。
