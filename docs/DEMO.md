# 《开铡》3—5分钟现场演示路线

这是一条建议讲解路线，按4分钟左右分配时间，**不是已测得的真人平均通关时长**。自动化通关测试只能证明路线可达，不能替代新玩家的理解时间。试玩评委可自行选择，作品不会通过隐藏文字或预设终局影响其判断。

## 演示准备

在已安装依赖的项目根目录运行 `npm run build`，再用 `npm run preview` 预览静态构建；不要把开发服务器作为公开的比赛生产站点。开演前检查目标设备的文字、声音、片头和存储状态。使用单独浏览器测试配置或无痕窗口，避免覆盖已有演示存档；若需重开，正常使用界面确认，不通过控制台注入进度。

在设置中将文字速度设为「迅捷」；点击正文可展开全文。现场为了展示玩法可跳过74秒片头，但应说明片头仍可完整观看。保持自动播放关闭，方便讲解和评委自由操作。

## 建议时间分配与操作

| 时间预算 | 操作路线 | 向评委展示的真实能力 |
| --- | --- | --- |
| 0:00—0:25 | 首页开始审案，必要时确认新卷宗；跳过片头，阅读第一堂「本堂要点」并升堂 | 保留原古风视觉、文化改编声明与四堂结构；无需额外教学弹窗 |
| 0:25—1:05 | 第一堂选择「先收状纸」「验看旧婚书」「调取原籍户籍」；其余按事实核查推进 | 玩家决定查问方法，证物实际进入卷宗；可打开「证物」查来处与查验要点 |
| 1:05—2:00 | 第二堂依次选「三方互核」「依方位勘血」「依法同验兵器架」「见证取纸」；进入关联案台 | 调查取证决定持有的物证，不是背景装饰 |
| 2:00—2:35 | 可先试婚书+钢刀，看到方向提示且证物不丢；再关联婚书+户籍、钢刀+刀鞘+腰牌、验状+遗书，关闭案台，选择逐组关联并结束本堂 | 同一套证物需要组成可证明的事实；失败与成功反馈不同，成功事实写入卷宗 |
| 2:35—3:15 | 第三堂依次选「并示婚书、户籍」「合验钢刀、同号刀鞘与腰牌」「以验状血痕印证遗书」；结束堂审 | 三项质询必须有证据，成功印证直接影响终审；可在失误时回退重问 |
| 3:15—4:00 | 第四堂按现有选项应对公主与懿旨，终审查看物证7/7、关联3/3、质询3/3，选择依律宣判并确认 | 王法与皇权的价值抉择，由真实卷宗决定结果，不靠随机抽签 |
| 4:00—4:30（可选） | 结局展开「判词依据 · 证据回顾」，再用原有「反悔 · 回到终审前」改选抗旨、移交或暂缓 | 四种不同结果可感知；规则解释与存档恢复可核对，不需从后台改数据 |

第一堂其余选择可优先采用核验/封存原件等方法；第二堂关联之后要再次选择「逐组关联，只写证物能证明之事」，才推进到下一节点。第三堂先推进陈世美开场和中间旁白；这两处不是卡死。

## 现场异常处理

- 如果显示自动存档失败，当前页面仍可继续，但刷新可能丢失本次进度；先核对存储权限/空间，恢复后继续一步并确认「自动存档已保存」。手动存档成功不代表自动档已经恢复。
- 自动档不可用而手动档可用时，继续案件会明确提示恢复的是手动卷宗。两个档都不安全时不会将异常对象交给页面渲染。
- 如果结局入档失败，页面会保留本次结局并告知未入档，不把失败写成成功。请勿以清空存档作为第一处理方式。
- 正式演示前应在真实比赛设备验证。自动化覆盖Chromium桌面/手机视口，不等同于所有实体手机、Safari或Windows Electron安装包已通过。

## 评分说明

可展示测试日志和实际界面，不虚构投票、留存率、通关时长或独立模型成绩。赛事单项公式为 `7h + 3a`（h、a分别为真实人类和AI投票比例）；缺少这些数据时，官方各项与总分均不可测。
