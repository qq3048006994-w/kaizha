## ⚠️ 首要声明：为什么本报告不输出具体分值

任务给定的计分规则为：

- 四个维度：实用性 10 分、技术性 10 分、美观性 10 分、趣味性 10 分
- 权重：人类评审 70%、AI 评审 30%
- 单项计分：`7 × 人类投票比例 + 3 × AI 投票比例`
- GPT-6.3 / Claude 只能作为**模拟参考**，实际评委以赛事现场配置为准

**要算出任何一个具体分值，必须同时具备真实的人类评委投票比例与真实 AI 评委投票比例。当前本地环境两者都不具备：**

1. 没有赛事现场的真实人类评委，也没有任何真实投票数据 → 不能编造「人类投票比例」。
2. 没有独立 GPT-6.3 / Claude 评委的授权接口与盲评结果 → 不能编造「AI 投票比例」。
3. 任务明确「严格禁止……伪造 AI 接口、伪造用户数据」→ 编造比例即属违规。

因此本报告**不输出任何分数、不输出任何投票百分比、不伪装成独立模型盲评结论**。
本报告的价值是：把四个维度逐项拆成**可核查的真实证据 + 优势 + 扣分风险 + 不投机的提升建议**，
让 Codex 云端修复完成后，赛事现场配置的真实评委能据此快速复评。
真实分值应由 `7 × 人类投票比例 + 3 × AI 投票比例` 在真实数据到位后计算，本报告不代算、不代填。

> 同理，「优化后复评」的具体分值也不由本地生成；应由 Codex 在分支上完成修复后，交由赛事现场评委配置产出。

## 三、四维度逐项评估（证据均可复核）

### 3.1 实用性（维度满分 10）

**可核查证据**

- 完全离线：`npm run build` 产出 `dist/`，无外部服务器、在线 API、在线图片依赖；字体 / 片头视频 / 立绘 / 背景全部随包。
- 完整可玩闭环：`test:e2e` 27 项真实走通首页 → 片头 → 第一堂 → 手动存档 → 刷新续档 → 第二堂关联 → 第三堂质询 → 第四堂终审二次确认 → 结局。
- 自动存档与恢复：`SAVE_VERSION=1`、损坏 / 版本不符有可读原因；探针实测刷新前后状态 `same=true`。
- 反悔机制：`test:undo` 21 项，支持跨堂回退、结局页「回到终审前」、卷宗逐条「回到此处」，快照上限 30 步。
- 片头可跳过、播完自动进入第一堂；片头画面已解码非黑屏（`1280×720`、`readyState=4`）。
- 桌面版结构就绪（Electron + NSIS 安装包配置），可脱离浏览器与命令行运行。
- 三档视口（1920×1080 / 1366×768 / 390×844）`horizontalOverflow=false`。

**优势**：开箱即用、无需账号与联网、存档与回退完善、多端一致。

**扣分风险**

- 片头在 390×844 下 `object-fit: cover` 裁切 16:9，标题只露中间部分（P3-3）。
- 未安装方正字体的机器回落到开源字体，与本机观感存在差异（P2-2）。
- 桌面版 `electron` / `electron-builder` 未预装，需额外一条安装命令才能出安装包（P3-5）。

**不投机的提升建议**：窄屏片头改 `contain` 或加遮幅；README 补齐回落态说明与截图；把桌面打包依赖写进一键脚本。

### 3.2 技术性（维度满分 10）

**可核查证据**

- 技术栈：React 18 + Vite 5（JavaScript）、CSS Variables + 单一入口样式表；状态机集中在 `src/App.jsx`，UI 由 `game.courtIndex / nodeId / phase` 数据驱动派生。
- 存档健壮性：`parseEnvelope()` 校验 JSON、对象类型、`version`、`state`、结局档案数组；`saveGame/loadGame/clearSave/recordEnding` 均不抛异常而返回可读失败原因；结局档案按 `endingId` 去重。
- 结局判定：纯函数 `evaluateEnding(state)`，判定顺序明确，未知 `finalChoice` 不擅作宣判；`REQUIRED_PROOF_FLAGS` 用 `Object.freeze` 冻结；`CORE_EVIDENCE_IDS` 冻结 7 件关键证物。
- 数据契约清晰：8 件证物 / 3 条 `evidenceLinks` / 4 条 `endingCatalog` 全为静态数据，UI 与逻辑解耦。
- 组件化：`CharacterPortrait` / `DialogueStage` / `SpeakerPanel` / `EvidenceLinkBoard` / `Typewriter`；立绘取图链支持回落且不跨角色、不镜像。
- 自动化程度：**14 条 npm 命令全部 `EXIT=0`**，含 9 个单元测试、27 项 E2E、21 项反悔、55 项章节字体、107 项舞台专项，以及 `check:nameplate / check:no-bold / check:archive-white / check:bust-white / check:fonts / check:dist` 六个像素级 / 规格级检查。
- `check-dist.mjs` 自带静态服务器与 SPA fallback，不依赖外部 preview 进程；`check:archive-white` 用 canvas 模拟 `cover` 做六档视口像素级断言。
- 运行期健康度：`consoleErrorCount=0`、`pageErrorCount=0`、`failedRequestCount=0`。
- 构建体积受控：CSS 56.88 kB / JS 212.87 kB，`built in 783ms`。

**优势**：状态机集中、判定为纯函数、失败路径有兜底、验收脚本密度高且自带服务器、无运行期错误。

**扣分风险**

- **P2-1（最主要）**：`e2e-endings.mjs` 通过注入终局 state 验证「结局页可达」，缺少「从四堂真实自然走到四种结局」的全流程端到端覆盖；单测覆盖判定逻辑，但不覆盖完整玩家路径。
- E2E 脚本硬编码系统 Edge 路径 `C:/Program Files (x86)/Microsoft/Edge/Application/msedge.exe`，换机需改 `executablePath` 或 `npx playwright install chromium`，可移植性有门槛。
- `dist/` 被 `.gitignore` 忽略，云端构建需自行 `npm run build` 后再 `check:dist`（已有 `KAIZHA_DIST` 支持，但需写进交付说明）。
- `README.md` 存在 2 处文档与实测不一致（P3-1「两款字体」、P3-2「39 项」实际 55 项），反映文档与测试未自动同步。

**不投机的提升建议**：补 `e2e-endings-flow.mjs` 四条自然路径；把浏览器路径改为可配置环境变量并回落到 Playwright 自带 Chromium；在 CI 中让文档检查数由脚本输出自动生成。

### 3.3 美观性（维度满分 10）

**可核查证据**

- 视觉体系：电影海报式首页、书法透明标题、宋代公堂背景、金色渐变 `background-clip:text` + 描边 + 多层投影浮雕大标题。
- 审案舞台：单人近景视觉小说式立绘（`*-bust.png`，统一 `641×730`），「谁说话谁出现」、人物恒不透明可遮挡背景、无半透明「幽灵」、无双人贴边空堂；`test:stage` 107 项校验四角透明 / 中心不透明 / 恰好 1 立绘 / 旁白 0 立绘。
- 抠图工艺：边界连通近白区域 + 按距离分层剥离灰白抗锯齿带 + 「邻域含深色」门控保护陈世美白袍 + 实体核心回填 + 最近前景色 RGB 填充；`check:bust-white` 实测 `robe_hole=0`；包拯银灰鬓髯采用 RGB-only 压暗保留发丝纹理，不挖透明洞。
- 人物档案：五张 `641×790` 纯白底半身照统一构图，`object-fit: cover; object-position: center top`；`check:archive-white` 六档视口底部非白占比 `0.865~0.969`，确认无下方空白。
- 排版细节：名牌文字框内真实居中（主文字偏移 `1.31px`、副标题 `0.33px`）；大标题统一 `font-weight:400` + `font-synthesis:none` + `1.6px` 描边，避免伪粗体。
- 字体：龙藏体（章节狂草）、霞鹜臻楷（醒目楷）、朱雀仿宋（正文瘦宋）分工明确；开源字体随包离线分发，含 OFL 许可文件。
- 三档视口无横向溢出，元素未错位。

**优势**：风格统一、古风肃穆有电影感；像素级验收覆盖白边 / 空白 / 居中 / 破洞等易翻车细节；字体授权处理干净。

**扣分风险**

- 方正宋刻本秀楷 / 方正清刻本悦宋**未获授权**，仅 `local()` 声明；评委机未安装时回落，标题与正文的观感与开发机不一致（P2-2）。
- 窄屏片头 `cover` 裁切影响第一印象（P3-3）。
- 侧身回落立绘缺 3 张（`princess-left` / `han-left` / `han-right`），当前回落通用立绘，虽不串角色但一致性略降（P3-4）。

**不投机的提升建议**：提供「授权字体到位前」的回落态对照截图并写进 README；窄屏片头改遮幅；补齐缺失立绘。不得以隐藏文字、叠加透明提示、诱导评委等方式干预观感评分。

### 3.4 趣味性（维度满分 10）

**可核查证据**

- 四种结局由游戏状态**计算得出，非随机**：`justice / defiance / power / pending`，分别对应「依法」「抗旨」「遵从懿旨」「证据不足 / 暂缓」，且 `yield` 与 `defer` 有独立判定优先级。
- 证据关联推演：3 条证据链（婚配与亲子 / 凶器与差遣 / 忠义两难），最多选 3 件、排序匹配、重复拦截、失败不显示标准答案只给方向提示；`c2_form_links` 要求 `linkCount>=3`。
- 第三堂多轮质询，6 个 `REQUIRED_PROOF_FLAGS` 全部命中才可进入正法 / 抗旨结局，质询结果真实影响结局。
- 反悔机制降低试错成本：跨堂回退、逐条「回到此处」、结局页「回到终审前」，快照上限 30 步。
- 结局档案按 `endingId` 去重解锁，首页可查看已解锁结局；8 件证物档案含来源、查验要点、关键印章。
- 逐字对话、惊堂木 / 翻页 Web Audio 合成音效、文字速度与自动播放 / 跳过已读设置。

**优势**：抉择有后果、证据链可推演、可回退探索多结局，叙事完整有沉浸感。

**扣分风险**

- 叙事为**线性四堂**，分支主要体现在终审选择与证据齐备度，缺少中途大幅分岔、随机事件或多周目变化，重玩驱动力有限。
- `evidenceLinks` 仅 3 条且固定组合，推演深度有限；缺证门禁是硬门槛而非渐进难度。
- 无计时、无评分、无成就系统（除结局档案），对偏好挑战的玩家激励较弱。
- 音频为 Web Audio 实时合成，无配乐层次变化；浏览器策略要求首次交互后才有声音。

**不投机的提升建议**：在不推翻现有四堂结构的前提下，可增加「卷宗批注」「分支对话差异」「结局达成条件提示」等轻量内容；**不得**通过隐藏提示、伪造 AI 反馈或操控评委来制造「有趣」的假象。

## 结论

本维度报告是**基于真实实测证据的模拟准备材料**，不产出分值、不产出投票比例、不伪装盲评。
四维度现状：实用性与技术性证据最扎实（离线闭环 + 14 条命令全绿 + 零运行期错误）；美观性有像素级验收支撑但受字体授权回落影响；趣味性有真实状态计算的多结局与证据推演，但线性叙事与固定证据链限制了重玩深度。
最值得优先处理的是 **P2-1（四结局自然触发全流程测试）** 与 **P2-2（字体回落说明）**，其余为文档与体验一致性问题。
