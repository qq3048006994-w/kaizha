## 3. 缺陷分级与复现

所有存档异常均使用全新 Playwright 上下文，不读取、清除或覆盖用户演示档。基线机器上的临时复现输出保存为 `/tmp/kaizha-review-baseline/probes.json`，关键结果另收入版本化证据摘要。

### P0

本次未确认 P0。不把“手动注入异常存档可白屏”写成“正常游玩必然丢档”。

### P1-01：异常存档进入渲染导致白屏

- 问题：`parseEnvelope` 仅检查 state 是对象；无法保证 courtIndex、nodeId、数组或快照安全。
- 复现：在独立测试上下文向 `kaizha:auto` 写入正常 version=1 状态，将 courtIndex 改为 99；刷新并点击继续。另将 evidence 改为 null 可复现同类故障。
- 实测：根节点变空；控制台分别出现 `Cannot read properties of undefined (reading 'nodes')`、`Cannot read properties of null (reading 'length')`。
- 涉及文件：`src/game/save.js`、`src/App.jsx`。
- 最小范围：读取时校验位置、字段类型和回退快照；保留坏档原文；让现有手动档 fallback 生效；保留版本号和正常档格式。
- 预期区别：原先崩溃，修改后留在首页给出错误；有健康手动档时恢复该档，不伪造进度。

### P1-02：“回到此处”目标错位

- 复现：第一堂先收状纸→继续→验看旧婚书→记录→第二条记录的“回到此处”。
- 实测：预期回到 `c1_marriage`，实际回到 `c1_plaint`。第一条记录没有对应按钮；栈超过 30 步后，列表索引与栈索引更不能等同。
- 涉及文件：`src/components/ArchiveModal.jsx`；不修改快照格式或 App 回退机制。
- 最小范围：按 snapshot.historyLength 找对应记录，只有快照仍保留时提供按钮。
- 预期区别：回到所点击的抉择之前，而不是早一步或裁剪后的错误位置。

### P2-01：展开全文后文字被定时器覆盖

- 复现：在 `c1_plaint` 开始逐字显示约 180ms 后点击文字，等待 80ms。
- 实测：51 字完整正文先出现，随后缩至 13 字，原 setInterval 仍运行。
- 涉及文件：`src/components/Typewriter.jsx`。
- 最小范围：保存计时器引用，展开时清理并避免重复完成回调。
- 预期区别：已展开正文保持完整；正常逐字动画与速度不变。

### P2-02：确认新开局后旧手动档仍存在

- 复现：保存第二堂手动档→返回首页→开始审案→确认另立新案→跳过片头。
- 实测：自动档为第一堂，手动档仍为第二堂。片头阶段旧自动档也尚未由游戏界面 effect 替换，刷新可能继续旧案。
- 涉及文件：`src/App.jsx`。
- 最小范围：确认后先成功写入新自动档，再清除旧手动档；写入失败时保留旧备用档并显示已有错误提示。
- 预期区别：确认文案与状态一致；取消保留所有旧档；结局档案与设置不清除。

### P2-03：打开菜单时自动播放继续推进

- 复现：第一堂旁白打开设置→开启自动播放→保持面板打开并等候完整文字和延迟结束。
- 实测：设置仍可见，底下 nodeId 从 `c1_arraign` 推进为 `c1_plaint`。
- 涉及文件：`App.jsx`、`pages/GamePage.jsx`。
- 最小范围：传入面板遮挡状态，遮挡时不安排自动推进；关闭后恢复。
- 预期区别：阅读/设置/关联期间不会漏过底层自动对话；不改变手动选择或自动播放时长。

### P2-04：测试证明范围不足与平台路径

`e2e-endings.mjs` 注入四种 ended 状态，只证明页面渲染，不能证明四种结局真实触发。原始 npm test 仅运行 9 个判定测试；没有存档与剧情图校验。浏览器/部分 npm 命令写死 Windows 个人目录，`check-fonts` 甚至把输出写入该目录形状。最小改进是独立平台适配、自然通关测试、可靠性测试、单元测试和统一入口，不改正式剧情数据。

### P2-05：开发依赖漏洞，不能作“零漏洞”声明

实际执行 `npm audit --json` 得到 6 个受影响依赖条目：1 high、5 moderate、0 critical。最高严重性来自 Vite；esbuild 与 minimatch 有直接公告，其余 ESLint 条目含传播依赖关系。不是 6 个生产游戏运行时漏洞，也不代表所有公告在本次 Linux 配置都可利用。

- Vite 5.4.21，公告包括 [GHSA-587h-7wmj-h5pm](https://github.com/advisories/GHSA-587h-7wmj-h5pm)（Windows 编辑器路径校验）和 [GHSA-4w7w-66w2-5vf9](https://github.com/advisories/GHSA-4w7w-66w2-5vf9)（优化依赖 sourcemap 路径）。
- esbuild：[GHSA-67mh-4wv8-2f99](https://github.com/advisories/GHSA-67mh-4wv8-2f99)，开发服务器跨源访问。
- minimatch：[GHSA-g3hv-75wg-m249](https://github.com/advisories/GHSA-g3hv-75wg-m249)，glob 放大拒绝服务。
- 审计工具建议 Vite 8 / ESLint 9 等主版本变更，需要单独升级与兼容性回归，不能 force 修复。本次不改依赖或锁文件。
- 保持开发服务器回环地址；现场静态演示使用构建产物。此措施不等于已修复上述漏洞。

### P2-06：异常存储的产品提示仍不完整

`autoSave`/`recordEnding` 返回错误，`App` 日常自动保存和结局入档未向玩家呈现失败；`resetGame` 也忽略 clearSave 返回值。可在浏览器覆盖 Storage 方法令其抛出异常后触发：底层函数返回 write-failed/clear-failed，但界面可能仍表现为正常保存/成功重置。新增单元测试可验证底层不抛异常，不能据此宣称界面已完善。应单独确认如何提示和保留进度；不扩大本次五项确认范围。
